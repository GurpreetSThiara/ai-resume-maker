# SEO & Policy Compliance Audit — CreateFreeCV.com

**Stack:** Next.js 16.0.10 (App Router), React 19, Vercel hosting (implied).
**Audit date:** 2026-08-30. **Method:** static code review + live inspection of the running dev server (read-only `curl`, no server restarts). Production behavior for anything gated by `NODE_ENV`/build output should be re-verified against a real deploy — noted inline where relevant.

No code was changed as part of this audit.

---

## Executive Summary — Top 5 by Impact

1. **`/robots.txt` returns HTTP 500 in production.** The project ships both `public/robots.txt` (static) and `app/robots.ts` (dynamic) — Next.js explicitly rejects this as a route conflict. Confirmed live: `curl localhost:3000/robots.txt` → `500` with a Next.js internal error page. Every crawler hitting this URL gets a server error instead of directives; sustained 5xx on robots.txt can cause Google to throttle or pause crawling of the whole site.
2. **Every Open Graph / Twitter Card image on the site is a 404.** `/og-image.png`, `/twitter-image.png`, `/og-cover-letter.png`, `/twitter-cover-letter.png`, `/og-image-converter.jpg`, `/twitter-image-converter.jpg`, and the entire `/blog/*.jpg` set are referenced in metadata across every page, but `public/` contains none of them and `public/blog/` doesn't exist at all. Every link shared on Slack, iMessage, LinkedIn, Twitter/X, or Facebook renders with a broken image.
3. **The sitemap submits 3 URLs that 404.** `app/sitemap.ts` lists `/software-engineer-resume`, `/ats-resume-explained`, and `/resume-rejected-without-interview` — none of these have a `page.tsx`; the real content lives only under `/blog/*`. This will surface as "Submitted URL not found (404)" in Search Console and signals poor site hygiene to Google.
4. **No cookie consent mechanism, despite GTM, Google Analytics, and PostHog loading unconditionally for every visitor.** GDPR/CCPA-relevant scripts fire before any consent is collected. Compounding this, the privacy policy shown at the actual point of consent (the signup modal) is a shorter, different document from the canonical `/privacy-policy` page and omits GTM and PostHog entirely.
5. **Private user dashboard pages have zero crawl/index protection.** `/dashboard/portfolios` and `/dashboard/portfolios/[id]/edit` have no `metadata`/`robots` export and no `layout.tsx`, so they inherit the root layout's `index:true`. Combined with the broken robots.txt (finding #1), there is currently *no* mechanism — meta tag or robots directive — preventing these from being indexed.
